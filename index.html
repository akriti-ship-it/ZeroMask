Detection Rules & Overlap Priority

        
Deterministic client-side scanners ordered from highest to lowest overlap precedence:
          CREDIT_CARD > AADHAAR > PAN > EMAIL > IP > PHONE
        

      

      

        

          
CREDIT_CARDPriority 1 (Highest)

          
Matches 13–19 digits with optional spaces or hyphens. Must pass Luhn (mod-10) and match Visa, Mastercard, Amex, Discover, or RuPay prefixes.

          
Partial: XXXX-XXXX-XXXX-1234

        

        

          
AADHAARPriority 2

          
Matches 12 digits starting 2–9 (plain or 4-4-4 space/hyphen grouped). Validated with the Verhoeff D5 checksum to filter random 12-digit IDs.

          
Partial: XXXX-XXXX-1234

        

        

          
PANPriority 3

          
Matches ^[A-Z]{5}[0-9]{4}[A-Z]$ with strict word boundaries and validates the 4th-character entity type (P,C,H,F,A,T,B,L,J,G).

          
Partial (first 2 + last 1): ABXXXXXXXF

        

        

          
EMAILPriority 4

          
RFC-style local@domain.tld matcher supporting dots, underscores, plus-tags, and subdomains. Normalized lowercase in pseudonym mode.

          
Partial: j***@domain.com

        

        

          
IPPriority 5

          
IPv4 with strict 0–255 octet checks and version-context exclusion (e.g. v1.2.3.4), plus full and compressed :: IPv6 addresses.

          
Partial: 192.168.X.X

        

        

          
PHONEPriority 6

          
Indian numbers (+91/0 prefix, 10 digits starting 6–9) and international E.164 numbers, bounded so they never match inside cards, Aadhaar, or order IDs.

          
Partial: +91-XXXXX-X1234

        

      

    


    
    

      

        
Zero-Egress Architecture

        
Built with plain HTML, CSS, and vanilla JavaScript so every byte stays inside your browser session.

      

      

        

          
1. Local File Ingestion

          
TXT and CSV files are read directly from disk via the browser FileReader API. No upload endpoint, cloud bucket, or external script exists.

        

        

          
2. Checksum-Verified Detection

          
Regex candidates pass algorithmic Luhn and Verhoeff checks plus boundary guards before overlap resolution removes duplicate or lower-priority spans.

        

        

          
3. Safe DOM Rendering

          
Highlights and diff views are constructed via DOM text nodes and escaped elements — never raw innerHTML injection — preventing XSS on untrusted inputs.

        

        

          
4. Ephemeral Mapping & Export

          
Pseudonym tables live strictly in JavaScript memory. Audit JSON exports exclude raw PII completely; sanitized files export via local Blob URLs.
